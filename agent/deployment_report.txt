TECHNICAL CHALLENGES ENCOUNTERED
---------------------------------
1. KEYBOARD AUTOMATION LIMITATION:
   - pyautogui/pywinauto send_keys keyboard events DO NOT work from background 
     terminal processes (SendInput requires foreground thread lock)
   - Mouse clicks (pyautogui.click) DO work
   - This means keyboard shortcuts like Ctrl+N, Alt+F cannot create new charts
   - auto_attach.py relies on send_keys for chart creation and menu navigation

2. CHART CREATION FAILURE:
   - Ctrl+N in this MT5 build does NOT open "New Chart" dialog
   - The script reports "No symbol dialog appeared after Ctrl+N"
   - Without chart creation, all EAs attach to the same chart (Replace dialog)
   - Market Watch right-click → Chart Window method is unreliable from background

3. VERIFICATION STALE LOGS:
   - auto_attach.py reads MT5 log files to verify EA attachment
   - When MT5 is restarted, old log entries from previous sessions cause
     false positives (script thinks old entry is from current attach)
   - Heartbeat verification has 60s timeout which often expires even on
     successful attachments

4. MT5 SESSION RESTORATION:
   - MT5 auto-restores previous workspace on restart
   - Killing MT5 requires multiple taskkill calls (MT5 has crash recovery)
   - Running with --restart flag failed because wait_for_mt5() uses UIA
     backend which doesn't work in this environment
